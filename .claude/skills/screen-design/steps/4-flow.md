# ステップ 4 / 6: 画面をつなぐ

**なぜやる。** 画面を分けると、画面から画面へ移る回数が生まれる。ジャーニーごとに、何回移るかを数えて、多すぎるところを見つける。
**できあがるもの。** `screens.yaml` の `journeys`(各ジャーニーが、どの画面で何をするか)。遷移の数は機械が数える。
**目安。** 45 分。

## やること
1. ジャーニーを 1 つ選ぶ(例: 「行きたい場所を見つけて、向かう」)。
2. 始点から終点まで、**利用者がやることを順に**、`{screen, do}` で書く。`do` は、概念のアクション(例: `Search.query`)。AI が下書きを出し、本人が直す。
3. 画面が変わる所が、遷移。`python3 tools/screen_check.py screens.yaml` で、ジャーニーごとの遷移の数と操作数が出る。
4. 多いところは、(a)相性を見直す、(b)画面に操作を足して遷移を減らす、のどちらかを考える。

## 評価基準
- [ ] すべてのジャーニーが、始点から終点まで書けている(到達)
- [ ] 各ジャーニーの遷移の数が、上限(`limits.max_transitions_per_journey`、未設定なら 3 を目安)以内
- [ ] 使われていない画面が無い(どのジャーニーにも出ない画面は、要らない画面)
- [ ] ジャーニーの終点で、完了が分かる(ステップ 5 で確かめる)
