## 1. 目的

- 価値: 来場者が、目当ての企画や駐車場を、名前の一部から探し出せる
- 目的(評価基準側): 来場者が、目当ての場所を、迷わず見つけられる  [proposed]
- 登場する人: 来場者

## 2. 使う概念と原理(基本シナリオの骨格)

- **Place**: 運営が場所の名前・種別・位置・説明を登録しておくと、来場者はその場所の一覧と個々の情報を見られる。
- **Search**: 項目に検索用の文字列を登録しておくと、来場者がキーワードで問い合わせたとき、 文字列にキーワードを含む項目が返る。

### 基本シナリオ(同期から導いた手順の候補)

1. 利用者が `Request.listPlaces` を求める → システムが `Place.list` を実行する。 TODO: 利用者に見えること
2. 利用者が `Request.showPlace` を求める → システムが `Place.get` を実行する。 TODO: 利用者に見えること
3. 利用者が `Request.registerPlace` を求める(条件: 実行者が場所を管理できる) → システムが `Place.register` を実行する。 TODO: 利用者に見えること
4. 利用者が `Request.search` を求める → システムが `Search.query` を実行する。 TODO: 利用者に見えること

連動(利用者の操作に続いてシステムが行うこと):
- `Place.register` のあと `Search.index`
- `Place.update` のあと `Search.index`(条件: name が更新された)
- `Place.remove` のあと `Search.unindex`

## 4. 評価基準

成功条件:
- 初めて使う人が、企画名の一部を入れてから、その場所の情報を見るまでを、説明なしで終えられる
- 検索の入力から結果の表示までが、体感で待たされない(目安: 1 秒以内)

失敗時の扱い:
- 一致する場所が無いとき、何も出ないのではなく、一致が無いことと次の手(別の言葉、一覧から探す)が分かる

デモの場面: 審査員が企画名の一部を入れて、場所の情報が出るところ

作らないこと: あいまい検索(誤字の補正), 読み仮名での検索
